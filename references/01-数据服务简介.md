# 数据服务简介

# 目前V2接口正在慢慢上新，地址、调用方式和格式都与V1有较大差异。V2会不定期更新并逐步补齐V1功能，请注意及时跟进。

RailGo 系列软件的设计理念是开放、现代与自由。有鉴于此，RailGo 的大部分数据都通过 API 数据服务对外开放。

您可以通过自动化程序访问 RailGo 数据，借此快速方便地实现获取和联动铁路信息。这些可以获取的数据，与 RailGo 应用内的在线查询保持一致。

> V2 版本开销比较大，所以响应时间会稍慢，算上网络延迟的话大约需要 1 秒左右，请合理设置 timeout 等待时间。

## 使用限制

现阶段 API 不设置 key 要求，不设置显式限速。但是，我们对您使用 API 的场合有如下要求：

- **不得**用于违反法律法规的用途。
- **不得**用于商业用途。此处的商业用途，指的是将获得本 API 提供的部分或全部信息的服务置于付费前提之下，或者付费且最终目的为获取经济利益的服务内使用本 API 提供的部分或全部信息，例如抽成的抢票平台。
- **不得**用于公开的接口中转服务。
- 在公开的软件服务或公开的自动生成信息（包括但不限于图片、文本）中使用来自本 API 的数据时，请您标注数据来源，并一并带上 RailGo 主站或数据服务文档的链接，置于显著位置。特别地，大学毕业设计等实验性使用不受此限制。

不设置显式限速并不代表您可以肆意抓取，因为您还是可能会被 CDN 屏蔽或封禁 IP。如果我们发现您在使用时违反了上面的三个**不得**，那么您的 IP 地址（或网段）也可能遭到长期封禁，请自重。

如果您想要大批量获取一手数据，那么您不应该派出爬虫抓取数据服务，而是应当直接自行部署 [RailGo-Parser](https://github.com/RailGoApps/RailGo-Parser)。

## 传参格式

通常情况下，传入所有接口的参数遵循以下规则：

- `boolean`：可以接受的表示“是”的值包括`1`、`true`、`True`、`yes`；可以接受的表示“否”的值包括`0`、`false`、`False`、`no`；
- 日期：可以接受的格式包括 `MMdd`，`MM.dd`，`MM-dd`，`yyyyMMdd`，`yyyy-MM-dd`，`yyyy.MM.dd` 等格式，其中前三种默认为当前年份。

## 对一些概念的解释

### I. 车次号与车次 ID

在 TMIS 系统内部，处理车次使用的是长的车次 ID，例如 `24000000G10L`，其中 `24` 代表维护该车次信息的部门，一般是车次始发站所在的资产公司/车务段；末位的 `L` 用于区分。

停靠站、担当公司等重要信息的变更会引起车次 ID 的变化。一个我们看到的车次号，例如 `G1` ，可能会对应多个车次 ID，且不同车次 ID 拿到的信息可能会有所差异。

RailGo 在返回的数据中保留车次 ID，但是强烈建议您不要使用他作为（如果需要的话）存储主键，而应当仅用于和其他平台交互，以免碰上运行图调整时搞混乱。

另外，中国铁路现行的车次编码规则中有出现多个车次对应同一列车的情况（学名复车次），例如 `G1202/1203` 指代同一列车。这是因为车次号的奇偶兼具了判断上下行的功能。相同日期的复车次指代的车次 ID 是一致的。

> 单号车次距离北京越来越远，双号车次距离北京越来越近；如果车次运行方向发生了转变，单双号会邻近转换；如果到北京的距离全程都差不多，则以上海为基准点。
> **注意：** 复车次有可能不止两个。

通常情况下，复车次的任意一个车次都可以传入 API 中，但是在部分情况下有例外，具体会说明。

### II. 同城车站与同地车站

RailGo 目前只能够提供到精确至地级市（直辖市、地区、省直辖县）的车站定位，然而这些行政区通常都比较大，如果用所属行政区来判断同城，有时会得到很离谱的结果。

例如，我想坐车前往重庆城区，如果按照行政区来算的话，`武隆`、`万州北` 等车站都是 `重庆市` 这一地区下的车站，但他们离我们认知上的重庆市显然非常遥远。


![重庆站到万州北站大约有 227.81km 的距离。](https://api.apifox.com/api/v1/projects/7299068/resources/670324/image-preview)

12306 人工维护了一个同城车站列表，比较准确的划定了“同一个城镇内”的车站的范围，比如上面这个例子中`万州北`的唯一同城车站是`万州`。

但是，出于为分析等目的提供方便的需要，RailGo 在提供 12306 版本的同城车站同时引入`同地车站`的概念，指的就是同属一个地级行政区的车站。比如上面这个例子中`万州北`就和`重庆`同地。

### III. 车站电报码

从技术规范的理论上看，一座车站的电报码是独一无二的。

然而现实中，存在`徐州东`和`雅周`共用了一个电报码`-UUH`的例外。为了处理这个例外情况，RailGo 对`徐州东`的电报码进行了转义，记作`-UUH/`。

传入电报码时，请手动除去可能存在的转义符号。

另请注意，由于 95306 基本不维护一些非货运车站的信息，可能会导致一些更名的车站被曾用名挤占，如`武汉东`被错误记为`流芳`，而电报码在此过程中不改变，可能会被误认为电报码重复。RailGo 已经尽力避免此种情况发生，但如果您确实遇到了这种错误信息，请提交反馈。

## 注意

RailGo 的所有数据都是自动采集的。由于上游可能会录入错误信息（对于 12306 这是家常事），我们**不对数据服务的准确性作任何保证**。

就像 RailGo 应用用户协议里写的一样，请不要使用数据服务的信息要求铁路运输企业做任何事。RailGo 的每一位开发者都不支持这种无理取闹的行径。

如果您需要使用我们的数据开展正式研究，建议您事先与我们取得联系。
